# npub-names — TypeScript mirror

TypeScript mirror of [npub-names](https://github.com/dakotad74/npub-names) algorithm **v1**,
validated against the same frozen vectors as the Java reference implementation.
The frozen algorithm lives in [`../SPEC.md`](../SPEC.md); this mirror and the Java library
must always agree.

Zero dependencies. Source ships as TypeScript and runs natively on Node ≥ 22.18 (native type
stripping) and in any bundler that consumes TypeScript (Vite, esbuild, tsx).

## Usage

```ts
import { generate } from "npub-names";

// Any accepted seed form of the same key yields the same name:
generate("npub16q4p5hsut68s72mwr4xf57u08ewx675tnsx3ute6fdwx6l50ng9sgt64q2").displayName();
// → "Paula Daniels Stanton Little"
generate("d02a1a5e1c5e8f0f2b6e1d4c9a7b8f3e5c6d7a8b9c0d1e2f3a4b5c6d7e8f9a0b").displayName();
// → "Paula Daniels Stanton Little"

const name = generate(someNpub);
name.given;             // "Paula"
name.surnames;          // ["Daniels", "Stanton", "Little"] (frozen, always 3, distinct)
name.number;            // 629 — deterministic disambiguator, show it only when needed
name.displayName();     // "Paula Daniels Stanton Little"
name.withNumber();      // "Paula Daniels Stanton Little 0629"
```

Invalid input (wrong HRP, payload not 32 bytes, bad checksum, mixed-case bech32, malformed
hex) throws.

## Wordlist integrity

The frozen wordlists are embedded (`src/wordlists.ts`, generated by
`tools/build-ts-wordlists.py` from the same frozen files the Java library loads) and their
SHA-256 checksums are verified at import time, per SPEC.md. A mismatch fails fast rather
than producing wrong names.

## Tests

```sh
npm test
```

The suite hardcodes the frozen vectors from SPEC.md. If a vector fails, the mirror is wrong.
